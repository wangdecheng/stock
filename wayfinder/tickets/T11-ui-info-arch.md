## Resolution

**决策（3 个子决策全部确定）：**

### 1. 页面清单：5 页 MVP 一起上

T5 已定 5 页 + T11 确认一起上：

| # | 页面 | 文件 | 核心组件 |
|---|---|---|---|
| 1 | 仪表盘 | `app.py` | 激活策略卡 + 真实持仓 + 虚拟账本曲线 + 今日建议 + 跑批按钮 |
| 2 | 股票详情 | `pages/1_股票详情.py` | 股票搜索 + K 线（Pyecharts + MarkPoint） + 财务摘要 + 历史信号回放 |
| 3 | 策略管理 | `pages/2_策略管理.py` | 列表 + 激活 + 参数表单（`__init__` 反射） + 跑批 + 历史 |
| 4 | 持仓管理 | `pages/3_持仓管理.py` | 真实持仓录入（data_editor） + 历史成交 + 虚拟账本切换 + 现金充值 |
| 5 | 回测 | `pages/4_回测.py` | 策略 + 时间 + 资金 → PnL 曲线 + 指标卡片 |

### 2. 移动端：桌面端为主

- iPad 宽度以上流畅
- 手机能看到，但布局可能拥挤（不专门优化）
- Streamlit 默认布局即可

### 3. 访问控制：裸跑 + 反代密码

- Streamlit 进程本身不鉴权
- 在 Nginx/Caddy 反代层加 basic auth（用户名密码）
- 反代也负责 HTTPS
- 不引入 streamlit-authenticator（多一个依赖）

## Question

Web UI 的页面结构和组件划分。MVP 阶段至少包含：

1. **首页 / 仪表盘**
   - 当前持仓概览（市值、盈亏、占比）
   - 今日操作计划（来自最近一次跑批）
   - 当前激活的策略 + 上次运行时间
2. **股票详情页**
   - K 线图（含买卖点叠加）
   - 财务/估值摘要
   - 当前策略视角下的历史信号回放
3. **策略管理**
   - 列出已注册的策略（来自 `strategies/` 扫描）
   - 选中激活、查看参数
   - 历史运行记录
4. **持仓管理**
   - 当前持仓表
   - 手动录入：买入/卖出表单
   - 历史成交记录
5. **回测**
   - 选策略 + 时间窗口 + 起始资金 → 看 PnL 曲线

约束：
- 单页应用也行、多页也行；按 T5 选定的框架定
- 信息密度适中，不要堆图表
- 移动端可读（不一定完美适配，至少不破）

期望：用户对页面清单 + 优先级拍板。
